02

Evaluation Criteria

Six metrics selected to reflect the severe class imbalance and asymmetric cost structure of fraud detection

Accuracy

The overall proportion of correct predictions. Reported for completeness, but is misleading in fraud detection — a model that always predicts "legitimate" scores ~96.5% accuracy on this dataset while catching zero fraud.

Precision

Of all transactions flagged as fraud, how many actually were? High precision reduces false alarms — crucial for customer experience, since incorrectly blocking a legitimate transaction damages trust and card holder satisfaction.

Recall (Sensitivity)

Of all actual fraudulent transactions, how many were caught? In fraud detection, each missed fraud (false negative) carries a direct financial loss, making recall the primary operational metric for risk teams.

F1 Score

The harmonic mean of precision and recall. A single balanced score especially suited to imbalanced datasets — it penalises models that sacrifice one metric to inflate the other, forcing genuinely balanced performance.

ROC-AUC

Threshold-independent discrimination power across all operating points. The standard competition metric for the IEEE-CIS challenge, reflecting how well the model separates fraud from legitimate transactions at any risk threshold a bank may choose.

Confusion Matrix

Full breakdown of TP, TN, FP, and FN at the chosen operating threshold (0.5). Translates abstract scores into concrete business impact — each FN is an undetected fraud transaction; each FP is a falsely declined legitimate purchase.

03

Testing Methodology

Consistent preprocessing and evaluation pipeline applied to both models on the IEEE-CIS dataset

Both models were evaluated on the IEEE-CIS Fraud Detection Dataset — released by Vesta Corporation for a Kaggle competition and widely used as a financial fraud benchmark. The dataset contains 590,540 e-commerce transactions with 433 features (transaction info, identity data, device fingerprints, and engineered Vesta features), of which only 3.5% are fraudulent — a severe real-world class imbalance.

Data Split

80/20 stratified train–test split (random seed 42), preserving the 3.5% fraud rate in both sets. All preprocessing fitted exclusively on training data to prevent leakage. Test set: 118,108 transactions.

Preprocessing

Missing values imputed with median (numerical) and mode (categorical). High-cardinality categoricals (card type, device info) label-encoded. Numerical features scaled with StandardScaler for Logistic Regression only. SMOTE oversampling applied to training set to address class imbalance.

Evaluation

All metrics computed on the held-out test set. Decision threshold fixed at 0.5 for scalar metrics. ROC-AUC computed from raw predicted probabilities. XGBoost trained with scale_pos_weight = 27.6 to reflect the 1:27.6 fraud-to-legitimate ratio.

05

Analysis & Recommendations

Context-specific guidance for financial organisations choosing between these two models

When to choose Logistic Regression

Logistic Regression is the right choice when regulatory explainability is non-negotiable — for example, under the EU AI Act or US Equal Credit Opportunity Act (ECOA), where institutions must provide clear reasons for adverse decisions (declined transactions, account freezes). Its lower compute requirements also make it suitable for real-time scoring on high-volume low-latency payment rails where XGBoost inference latency is unacceptable. Use as a transparent first-pass filter or for compliance reporting.

When to choose XGBoost

XGBoost is the clear production choice for maximising fraud catch rate. Its recall of 73.5% vs 37.2% translates to 1,512 additional fraud cases caught per 118,108 transactions. At an average e-commerce fraud transaction value of $150–$200, that gap represents $226,800–$302,400 in recovered losses per test-set period — far exceeding the cost of false alarms. SHAP values provide post-hoc explainability for regulatory audits.

Key Takeaway

On the IEEE-CIS fraud detection benchmark, XGBoost is the recommended production model for any financial organisation where fraud loss minimisation is the primary objective. It catches nearly twice as much fraud (73.5% vs 37.2% recall), flags fewer false alarms (393 vs 694 FP), and achieves an ROC-AUC of 0.934 — approaching top-tier competition performance. Logistic Regression remains a valuable interpretable baseline and is recommended for compliance layers, regulatory reporting, and latency-constrained environments where a model coefficient explanation is required per transaction decision.

Evaluation Summary

On the IEEE-CIS Financial Fraud Detection dataset, XGBoost outperforms Logistic Regression on every metric — most critically catching 1,512 more fraudulent transactions per test period while simultaneously generating fewer false alarms. The performance gap reflects the fundamentally non-linear nature of fraud: transaction velocity, device fingerprint combinations, and behavioural anomalies require ensemble methods to detect reliably. Multi-metric evaluation remains essential — accuracy alone would falsely suggest both models perform identically well.
